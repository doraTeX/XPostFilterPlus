# 実装構成

- `src/content/posts.ts`：ポスト本文を抽出。引用・カード・操作UIを除き、本文内の絵文字の代替テキストを保持します。
- `src/content/engine.js`：ポストIDと本文で表示枠の再利用を検出。非表示、条件別の一時解除、近傍ポストの判定キュー、設定反映を担当します。
- `src/background/controller.js`：接続先の選択、キーの保持、同時実行制御、同一入力の重複送信抑制、予算上限、キャッシュ、設定の競合検出を担当します。
- `src/background/index.ts`：Chrome APIと通信処理。設定操作は拡張自身のページに限定し、Xのコンテンツスクリプトには認証情報を返しません。
- `src/shared/ai.js` / `ai-errors.js`：接続先ごとのリクエスト・応答形式、エラー分類。
- `src/dashboard`：元のXページに重ねる設定ダイアログ。自動保存、JSON移行、設定履歴、停止解除、キャッシュ削除を提供します。

非表示には専用の `data-xpf-hidden` 属性を付けます。一時解除や終了時にはこの属性だけを除去し、他の拡張・ユーザースクリプトが設定したインラインスタイルや目印を変更しません。

判定結果は条件・接続先・本文を含む識別子に結び付けます。設定変更やキャッシュ削除前に開始した応答は、変更後の結果として使用・保存しません。サービスワーカーが停止・再起動しても、保存済みのキャッシュと重大エラー状態を引き継ぎます。

ポスト単位の失敗は「非該当」として扱わず、結果が得られなかったものとして短時間記録します。接続先全体のエラーには待機または停止状態を保存し、並行処理の成功で重大エラーを取り消さないようにします。

- `src/content/overlay.ts`：Y!News Filter Plusと共通のチップ・条件タグ・進捗・回転矢印。タグDOMを保持してフォーカスを維持します。
- `src/shared/keyword-rules.js`：元の照合・行指定・除外率・重複整理を流用。
- `src/shared/sync.ts` / `src/background/sync-store.ts`：元のベクター時計・分割保存・競合解決を流用。
- `public/_locales/en` / `ja`：RakuFillと同じChrome標準i18n。未翻訳キーとプレースホルダーの不一致をビルド時に検出します。

設定画面は開いた元のXタブに自動対応します。キーワード・AI条件はすべてのXタブで共有し、使用量・一時表示・判定詳細は元のXタブに対応します。

キーワードの規則は照合設定が変わったときだけ作り直します。正規化済みの本文は最大500ポスト、除外率の判定結果は現在のタイムライン内で最大2,000ポストまで保持します。一時解除中の語はカウンターを進めず、次の一致規則へ進みます。

同期操作と設定編集はControllerの同じ書き込み列に通し、同期用の変更記録も設定保存とまとめます。永続アラームで、有効なChrome同期を5分ごとに再確認・再試行します。AIキャッシュは実際に送る日英の指示文ごとに分けます。ダッシュボードの定期取得では判定行を省略し、判定表は直近5件（合計6MBまで）をセッション内に保持して再読み込みに対応します。

チップとツールバーは、元のXタブ内にY!News版と同じ寸法・外観のネイティブdialogを開きます。閉じたShadow DOMに、既存の拡張オリジンの設定UIをiframeで載せます。追加公開するHTMLは設定画面だけで、APIキーは信頼済みの拡張フレームとバックグラウンド内で扱います。埋め込まれた画面の操作には、開いたタブごとの推測困難なセッショントークンを必須とします。無断で埋め込んだ画面には設定やキーを返しません。閉じる・タブ終了・X/Twitter以外への移動で許可を失効し、「閉じる」でXタブ自体を閉じないようにしています。

Escは設定UIへ転送し、入力欄にフォーカスがある間は閉じず、それ以外では保存を待って閉じます。ブラウザの接続許可は利用者のクリック中に設定UIから直接開始し、バックグラウンドは実際の権限を確認してからキー確認を実行します。確認ダイアログとTSVのコピーは元ページ側で行い、その経路にAPIキーを渡しません。判定行の投稿者は検証したアカウント名とXのプロフィールリンクを表示し、AIには送信しません。

Chrome仕様：[web-accessible resources](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources)。

ページ側で設定画面を開けない場合は、元のXタブIDを引き継ぐ設定タブを再利用して案内します。トップフレームの起動通知で再読み込み前の許可を失効します。保存完了前にネイティブdialogが閉じても同じフレームを再表示し、認証済みの閉じる応答を受けてから破棄します。


content scriptは、入口の`/`にいる間とXの`main`要素がまだない間、ページ状態の読み取りだけで起動を待ちます。この間は画面遷移を強制せず、チップの追加やポストの非表示も行いません。X自身のルーティングとメイン画面の組み立てが済んだら既存のエンジンを起動します。ポストの存在は起動条件にしないため、空のタイムラインや検索結果でも利用できます。接続切れでは待機を終了し、タイマーと監視を解除します。


古い設定フレームの許可を失効させた後、Xの画面準備を待つより前に設定用の受信処理を登録します。フィルターが未起動でも、利用者の操作による設定ダイアログの開閉・確認・コピーは認証済みの経路で利用できます。軽量な状態取得ではXの画面準備待ちと案内し、フィルター起動までは一時的な全件表示を無効にします。エンジンの起動後は同じ受信処理に接続し、重複登録しません。


判定行はポストごとの診断データを参照し、多条件でも送信本文とログを重複転送しません。処理ログは直近20件、表示変更ログはポストごとに直近40件、各監視記録は現在のビュー内で最大500件まで保持します。明示的な判定表・TSV・Console出力に診断データを含め、定期的な件数取得には含めません。詳細のDOMは展開時に作成。保存した表では診断データも同じセッション記録に含め、従来の直近5件・合計6MBの上限を維持します。キャッシュ・共有処理の判定対象本文は、このタブからの新規送信と区別して表示します。
